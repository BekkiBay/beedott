# Настройки саммари: модель и инструкция фоллоу-апа — дизайн

Дата: 2026-10-14. Статус: согласован с пользователем (модели: Opus 5.5,
Sonnet 5.5, Fable 5.1; редактируется вся инструкция, технический формат
скрыт).

## Цель

В «Настройке…» на шаге «Саммари» пользователь выбирает модель Claude для
фоллоу-апов и редактирует текст инструкции, по которой Claude их пишет.
Сломать фоллоу-ап правкой текста нельзя: формат ответа (ключи JSON) BeeDott
добавляет сам.

## Решения

- **Модели** (все проверены 2026-10-14 через Models API и тестовым саммари
  тем же запросом, что шлёт BeeDott, — код запроса не меняется):

  | id | Подпись в мастере | Цена вход / выход, $ за 1 млн токенов |
  |---|---|---|
  | `claude-opus-5-5` | Opus 5.5 — по умолчанию, лучшее качество за свои деньги | 4 / 20 |
  | `claude-sonnet-5-5` | Sonnet 5.5 — быстрее и в 2 раза дешевле | 2 / 10 |
  | `claude-fable-5-1` | Fable 5.1 — самая сильная, в 2,5 раза дороже Opus | 10 / 50 |

  Хранится в `config.env` как `ANTHROPIC_MODEL` (как сейчас); после смены
  демон перезапускается тем же `applyNewSettings`, что и после ключа (во время
  записи или обработки — «Применится после текущей встречи»). Выбор модели
  есть только при способе саммари `api`; для `claude_cli` (dev) — не
  показывается.
- **Инструкция** хранится в `app_dir()/followup_instructions.md`. Нет файла
  или он пустой — стандартная инструкция из кода. Демон читает файл перед
  каждым саммари (API и `claude -p`), перезапуск не нужен. Сброс — удалить
  файл.

## Python: промпт (`daemon/summarizer.py`)

Сейчас промпт — два куска: `SYSTEM_PROMPT` (стиль) и `_SCHEMA_RULES` в
пользовательском сообщении (что писать в каждом разделе + правила + формат
JSON). Новая раскладка:

- `DEFAULT_INSTRUCTIONS` — стиль из `SYSTEM_PROMPT` + описание разделов
  (`context`, `discussed`, `decisions`, `action_items`, `open_questions` — что
  в них писать, сколько пунктов, как формулировать задачи, кто такой «Спикер
  1/2») + содержательные правила (не выдумывать, даты по-человечески).
  Тексты переносятся из нынешних `SYSTEM_PROMPT` и `_SCHEMA_RULES` без
  изменений смысла.
- `_FORMAT_RULES` — только технический хвост, не редактируется: один
  JSON-объект с ключами `context` (строка), `discussed`, `decisions`,
  `open_questions` (списки строк), `action_items` (объекты `task`, `owner`,
  `deadline` = `YYYY-MM-DD` | `"asap"` | `null`); пустой раздел — `[]` или
  `""`; набор ключей строго по схеме; без markdown-обёртки и преамбулы.
- `load_instructions() -> str` — текст из файла, если он есть и после
  `strip()` не пустой, иначе `DEFAULT_INSTRUCTIONS`. Ошибка чтения файла —
  стандартная инструкция + предупреждение в лог (саммари не падает).
- Запрос: `system` = `load_instructions()`; пользовательское сообщение
  (`build_prompt`) = подсказки (участники, дата) + транскрипт +
  `_FORMAT_RULES`. `claude_cli` — `--append-system-prompt load_instructions()`.
- `SYSTEM_PROMPT` и `_SCHEMA_RULES` как публичные имена уходят; все их
  использования (`anthropic_api.py`, `claude_cli.py`, тесты) переводятся на
  новые.

## Python: команды `daemon/setup.py`

Протокол прежний (JSON-события, `ok` / `error`). Текст инструкции — только
через stdin.

| Команда | Что делает | `ok` |
|---|---|---|
| `summary-settings` | Текущие настройки | `{"model": str, "instructions": str, "custom": bool, "default_instructions": str}` |
| `set-model` | stdin: id модели. Не из списка выше → `bad_model`. `update_config_env("ANTHROPIC_MODEL", id)` | `{"model": id}` |
| `set-instructions` | stdin: текст. Пустой после `strip()` или равный стандартному → файл удаляется. Длиннее 20 000 символов → `too_long`. Иначе атомарная запись (временный файл + `os.replace`) | `{"custom": bool}` |

`model` в `summary-settings` — значение, которое увидит демон
(`_setting("ANTHROPIC_MODEL")`, иначе дефолт `config.py`). `status` получает
поле `summary_model` с тем же значением (мастеру не нужен лишний вызов на
входе в шаг).

## Swift: шаг «Саммари» и окно инструкции

**Шаг «Саммари»** (`SummaryStepView`), когда ключ уже сохранён и способ —
`api`, под строкой «Anthropic API — ключ сохранён»:

- «Модель» — три строки-радиокнопки с подписями из таблицы. Выбор сразу
  вызывает `set-model`, затем `applySettings()`; строка состояния под списком
  («Сохраняю…», ошибка, `applyNote`). Значение `summary_model`, которого нет
  в списке (ручная правка `config.env`), показывается отдельной строкой
  «Сейчас: <id>», ни одна радиокнопка не выбрана.
- Кнопка «Инструкция для фоллоу-апов…» (видна при любом способе саммари,
  когда он настроен) открывает окно инструкции. Рядом — «своя» / «стандартная».

Окно 520×460 не растёт: список моделей — компактный, по одной строке на
модель.

**Окно инструкции** (`InstructionsWindow`, отдельное `NSWindow`, 640×560,
можно растягивать; повторное открытие показывает то же окно):

- при открытии — `summary-settings`, спиннер до ответа;
- `TextEditor` с текстом (системный шрифт 13 pt);
- под полем: «Формат ответа (разделы и JSON) BeeDott добавляет сам. Новая
  инструкция применится к следующим встречам; пересобрать старую —
  Библиотека → «Пересобрать саммари»»;
- кнопки: «Сбросить к стандартной» (подставляет `default_instructions` в
  поле, сохраняет только по «Сохранить»), «Отмена», «Сохранить»
  (`set-instructions`, по успеху окно закрывается); ошибки `too_long` /
  `internal` — текстом над кнопками;
- закрытие с несохранёнными правками — `NSAlert` «Сохранить изменения?»
  («Сохранить» / «Не сохранять» / «Отмена»).

Тексты ошибок по кодам — в `RuntimeLogic.setupErrorText`: `bad_model` →
«Такой модели нет в списке», `too_long` → «Инструкция длиннее 20 000
символов — сократи».

## Тесты

- **pytest `tests/test_summarizer.py`** (или существующий файл промптов):
  `load_instructions` — нет файла → стандартная; пустой/пробельный → стандартная;
  свой текст → он; ошибка чтения → стандартная. `build_prompt` содержит
  транскрипт и `_FORMAT_RULES`, но не содержит текст инструкции.
  `DEFAULT_INSTRUCTIONS` содержит все пять ключей разделов.
- **pytest `tests/test_anthropic_api.py`**: `system` в запросе = свой текст
  из файла, если он есть.
- **pytest `tests/test_claude_cli.py`** (если есть тест на аргументы): своя
  инструкция уходит в `--append-system-prompt`.
- **pytest `tests/test_setup.py`**: `set-model` пишет `ANTHROPIC_MODEL`,
  чужой id → `bad_model`; `set-instructions` пишет файл, пустой и равный
  стандартному — удаляет, длинный → `too_long`; `summary-settings` и
  `status.summary_model` отдают текущие значения.
- **Качество:** после переноса текстов пересобрать саммари одной прошлой
  встречи стандартной инструкцией и сравнить с прежним фоллоу-апом —
  разделы и стиль на месте, задачи не потерялись. Делается вручную при
  реализации.
- **Вручную:** сменить модель в «Настройке…» → следующий фоллоу-ап с меткой
  `anthropic-api:<id>`; своя инструкция («пиши всё капслоком») → пересборка
  встречи даёт капслок, ключи JSON на месте; «Сбросить к стандартной» →
  файла нет.
