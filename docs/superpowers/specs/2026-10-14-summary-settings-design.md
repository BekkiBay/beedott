# Настройки саммари: модель и инструкция фоллоу-апа — дизайн

Дата: 2026-10-14. Статус: согласован с пользователем (модели: Opus 5.5,
Sonnet 5.5, Fable 5.1; редактируется вся инструкция, технический формат
скрыт).

## Цель

В «Настройке…» на шаге «Саммари» пользователь выбирает модель Claude для
фоллоу-апов и редактирует текст инструкции, по которой Claude их пишет.
Формат ответа (ключи JSON) BeeDott добавляет сам, поэтому правка текста не
ломает фоллоу-ап: через API структуру ещё и гарантирует structured outputs. В
dev-режиме `claude -p` гарантии нет — фраза вроде «ответь списком» может
перебить требование JSON, тогда стадия уйдёт в `failed_retry`.

## Решения

- **Модели** (все проверены 2026-10-14 через Models API и тестовым саммари
  тем же запросом, что шлёт BeeDott, — код запроса не меняется):

  | id | Подпись в мастере | Цена вход / выход, $ за 1 млн токенов |
  |---|---|---|
  | `claude-opus-5-5` | Opus 5.5 — по умолчанию, лучшее качество за свои деньги | 4 / 20 |
  | `claude-sonnet-5-5` | Sonnet 5.5 — быстрее и в 2 раза дешевле | 2 / 10 |
  | `claude-fable-5-1` | Fable 5.1 — самая сильная, в 2,5 раза дороже Opus | 10 / 50 |

  Хранится в `config.env` как `ANTHROPIC_MODEL` (как сейчас); после смены
  демон перезапускается тем же `applyNewSettings`, что и после ключа (во время
  записи или обработки — «Применится после текущей встречи»). Выбор модели
  есть только при способе саммари `api`; для `claude_cli` (dev) — не
  показывается. Список трёх id — одна константа `SUMMARY_MODELS` в
  `daemon/setup.py`; Swift держит те же id с подписями, совпадение проверяет
  pytest (по образцу проверки `MODEL_REPO`).
- **Инструкция** хранится в `app_dir()/followup_instructions.md`. Нет файла
  или он пустой — стандартная инструкция из кода. Демон читает файл перед
  каждым саммари (API и `claude -p`), перезапуск не нужен. Сброс — удалить
  файл.

## Python: промпт (`daemon/summarizer.py`)

Сейчас промпт — два куска: `SYSTEM_PROMPT` (стиль, в `system`) и
`_SCHEMA_RULES` в пользовательском сообщении после транскрипта (что писать в
каждом разделе + правила + формат JSON). Новая раскладка сохраняет главное —
подробные правила идут после транскрипта (на длинном контексте инструкции
после документа соблюдаются лучше):

- `SYSTEM_PROMPT` — короткая фиксированная роль: «Ты пишешь фоллоу-ап по
  рабочей встрече по инструкции из сообщения пользователя.» Не редактируется.
- `DEFAULT_INSTRUCTIONS` — стиль из нынешнего `SYSTEM_PROMPT` + описание
  разделов (`context`, `discussed`, `decisions`, `action_items`,
  `open_questions` — что в них писать, сколько пунктов, как формулировать
  задачи, кто такой «Спикер 1/2») + содержательные правила (не выдумывать,
  даты по-человечески). Тексты переносятся из нынешних `SYSTEM_PROMPT` и
  `_SCHEMA_RULES` без изменений смысла.
- `_FORMAT_RULES` — только технический хвост, не редактируется: один
  JSON-объект с ключами `context` (строка), `discussed`, `decisions`,
  `open_questions` (списки строк), `action_items` (объекты `task`, `owner`,
  `deadline` = `YYYY-MM-DD` | `"asap"` | `null`); пустой раздел — `[]` или
  `""`; набор ключей строго по схеме; без markdown-обёртки и преамбулы.
- `load_instructions() -> str` — текст из `app_dir()/followup_instructions.md`,
  если файл есть и после `strip()` не пустой, иначе `DEFAULT_INSTRUCTIONS`.
  Ошибка чтения файла — стандартная инструкция + предупреждение в лог (саммари
  не падает).
- Запрос: `system` = `SYSTEM_PROMPT`; пользовательское сообщение
  (`build_prompt`) = подсказки (участники, дата) + транскрипт +
  `load_instructions()` + `_FORMAT_RULES`. `claude_cli` — так же
  (`--append-system-prompt SYSTEM_PROMPT`, текст — через `build_prompt`).
- `_SCHEMA_RULES` уходит; его использования (тесты) переводятся на новые имена.

## Python: команды `daemon/setup.py`

Протокол прежний (JSON-события, `ok` / `error`). Разбор stdin в `main()`:
сейчас читается одна строка только для `SECRET_COMMANDS`; `set-model` читает
первую строку, `set-instructions` — весь stdin (`sys.stdin.read()`),
иначе от многострочной инструкции останется первая строка. Swift `runSetup`
дописывает к stdin `"\n"`, поэтому все сравнения — после `strip()` с обеих
сторон.

| Команда | Что делает | `ok` |
|---|---|---|
| `summary-settings` | Текущие настройки | `{"model": str, "instructions": str, "custom": bool, "default_instructions": str}` |
| `set-model` | stdin: id модели. Не из списка выше → `bad_model`. `update_config_env("ANTHROPIC_MODEL", id)` | `{"model": id}` |
| `set-instructions` | stdin: весь текст. После `strip()` пустой или равный `DEFAULT_INSTRUCTIONS.strip()` → файл удаляется. Длиннее 20 000 символов → `too_long`. Иначе атомарная запись (временный файл + `os.replace`) | `{"custom": bool}` |

`model` в `summary-settings` — значение, которое увидит демон
(`_setting("ANTHROPIC_MODEL")`, иначе дефолт `config.py`). `custom` — файл
инструкции есть и после `strip()` не пустой. `status` получает поля
`summary_model` и `summary_custom` с теми же значениями (мастеру не нужен
лишний вызов на входе в шаг).

## Swift: шаг «Саммари» и окно инструкции

**Шаг «Саммари»** (`SummaryStepView`), когда ключ уже сохранён и способ —
`api`, под строкой «Anthropic API — ключ сохранён»:

- «Модель» — выпадающий список (`Picker`, стиль меню) с тремя моделями и под
  ним одна строка-подпись выбранной модели из таблицы. Выбор сразу вызывает
  `set-model`, затем `applySettings()`; строка состояния под списком
  («Сохраняю…», ошибка, `applyNote`). Значение `summary_model`, которого нет
  в списке (ручная правка `config.env`), показывается в списке отдельным
  пунктом «<id> (вручную)».
- Кнопка «Инструкция для фоллоу-апов…» (видна при любом способе саммари,
  когда он настроен) открывает окно инструкции. Рядом — «своя» / «стандартная»
  по `summary_custom`; после «Сохранить» в окне колбэк обновляет это значение в
  `SetupModel`.

**Нет `status`.** На чистом Mac мастер открывается до установки рантайма, и
`status` равен `nil` (`checkSetupOnLaunch` и «Настройка…» зовут `status`
только при установленном рантайме). Тогда модель — дефолт `claude-opus-5-5`,
`custom` — `false`: на свежем Mac ни `ANTHROPIC_MODEL`, ни файла инструкции
нет, так что это и есть правда. После `check-key` список появляется с этими
значениями без повторного `status`.

Окно 520×460 не растёт: модель — одна строка списка и одна строка подписи.

**Окно инструкции** (`InstructionsWindow`, отдельное `NSWindow`, 640×560,
можно растягивать; повторное открытие показывает то же окно):

- при открытии — `summary-settings`, спиннер до ответа; ошибка — текст и
  «Повторить», «Сохранить» недоступна;
- `TextEditor` с текстом (системный шрифт 13 pt);
- под полем: «Формат ответа (разделы и JSON) BeeDott добавляет сам. Новая
  инструкция применится к следующим встречам; пересобрать старую —
  Библиотека → «Пересобрать саммари»»;
- кнопки: «Сбросить к стандартной» (подставляет `default_instructions` в
  поле, сохраняет только по «Сохранить»), «Отмена», «Сохранить»
  (`set-instructions`, по успеху окно закрывается); ошибки `too_long` /
  `internal` — текстом над кнопками;
- «Отмена» закрывает без вопроса (явный отказ); закрытие крестиком окна с
  несохранёнными правками — `NSAlert` «Сохранить изменения?» («Сохранить» /
  «Не сохранять» / «Отмена»).

Тексты ошибок по кодам — в `RuntimeLogic.setupErrorText`: `bad_model` →
«Такой модели нет в списке», `too_long` → «Инструкция длиннее 20 000
символов — сократи».

## Тесты

- **Изоляция.** Autouse-фикстура в `tests/conftest.py` ставит
  `MEETMIND_APPDIR` во временный каталог для всех тестов (тест со своей
  фикстурой `appdir` переопределяет). Иначе `load_instructions()` в тестах
  прочитает настоящий файл инструкции пользователя. Фикстура `appdir` в
  `tests/test_setup.py` дополнительно убирает `ANTHROPIC_MODEL` из
  окружения (`import config` кладёт его туда из `.env`, а `_setting` берёт
  окружение раньше `config.env`); `test_status_clean_mac` ждёт новые поля
  `summary_model` и `summary_custom`.
- **pytest `tests/test_summarizer.py`** (или существующий файл промптов):
  `load_instructions` — нет файла → стандартная; пустой/пробельный → стандартная;
  свой текст → он; ошибка чтения → стандартная. `build_prompt` содержит
  транскрипт, затем инструкцию (свою, если есть), затем `_FORMAT_RULES`.
  `DEFAULT_INSTRUCTIONS` содержит все пять ключей разделов.
- **pytest `tests/test_anthropic_api.py`**: `system` = `SYSTEM_PROMPT`; своя
  инструкция из файла — в пользовательском сообщении.
- **pytest `tests/test_claude_cli.py`**: `--append-system-prompt` =
  `SYSTEM_PROMPT`, своя инструкция — в промпте.
- **pytest `tests/test_setup.py`**: `set-model` пишет `ANTHROPIC_MODEL`,
  чужой id → `bad_model`; `set-instructions` пишет файл, пустой и равный
  стандартному (в том числе с `"\n"` в конце) — удаляет, многострочный текст
  сохраняется целиком, длинный → `too_long`; `summary-settings` и
  `status.summary_model` / `summary_custom` отдают текущие значения;
  id в `SUMMARY_MODELS` совпадают с id в `SetupWizard.swift`.
- **app/Tests:** `setupErrorText` для `bad_model` и `too_long`.
- **Качество:** после переноса текстов прогнать `anthropic_api.summarize`
  напрямую (без демона и доставки в Telegram) на 3 прошлых встречах, включая
  самую длинную, и сравнить с их прежними `followup.json` — разделы и стиль на
  месте, задачи не потерялись. Делается вручную при реализации.
- **Вручную:** сменить модель в «Настройке…» → следующий фоллоу-ап с меткой
  `anthropic-api:<id>`; своя инструкция («пиши всё капслоком») → пересборка
  встречи даёт капслок, ключи JSON на месте; «Сбросить к стандартной» →
  файла нет.
